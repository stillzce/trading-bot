# Трейдинг-бот у Telegram

**Робочий час:** пн–пт, 08:00–23:00 за Києвом.

- **О 08:00 бот надсилає денний контекст по кожному інструменту.** Контекст визначається денною свічкою (закриття о 17:00 NY = 00:00 Київ) відносно попередньої:
  - закрилась вище PDH або зняла PDL і повернулась → 🟢 BULL;
  - закрилась нижче PDL або зняла PDH і повернулась → 🔴 BEAR;
  - inside-день або outside-день із закриттям всередині → ⚪ нейтрально. Тоді бот бере контекст зі свічки днем раніше, а якщо й вона нейтральна, то ще раніше (до 5 днів).

  До звіту додаються рівні PDH/PDL, WT на D і денний графік.
- **Щохвилини бот перевіряє WaveTrend на M1, M5, M15, M30, H1, H4 і D1.** Сигнал надсилається тільки на екстремумі й тільки за контекстом:
  - BULL → перетин WT вгору на **дні** (≤ −60) → 🟢 LONG;
  - BEAR → перетин WT вниз на **вершині** (≥ 60) → 🔴 SHORT.

  Якщо кілька таймфреймів дали сигнал одночасно, бот надсилає одне повідомлення з графіком старшого з них.

**Джерело даних** вибирається автоматично, у такому порядку:
1. **TradeLocker** (секрети `TL_EMAIL`, `TL_PASSWORD`, `TL_SERVER`): акаунт окремий, не пропу;
2. **OANDA** (секрет `OANDA_TOKEN`, API-токен з демо-рахунку OANDA);
3. **Yahoo**: запасне джерело без акаунтів. Ф'ючерси й індекси там із затримкою 10–30 хв, тому для US500/NAS100/GER40/XAUUSD сигнали йдуть лише з M15.

## Безкоштовні ліміти — важливо

Бот працює 15 год на день, тобто приблизно 20 000 хвилин GitHub Actions на місяць. Приватний репозиторій дає лише 2000 безкоштовних хвилин, а **публічний — без ліміту**. Тому репозиторій має бути **публічним**:
- секрети (паролі, токени) **не видно нікому**, навіть у публічному репозиторії;
- видно лише код бота, а в ньому немає нічого особистого.

## Налаштування (≈15 хв)

1. **Telegram.** У @BotFather створи бота (`/newbot`) і скопіюй токен. Напиши своєму боту `/start`. Свій chat_id дізнайся в @userinfobot.
2. **GitHub.** Створи **публічний** репозиторій і додай у нього 4 файли, зберігши шляхи: `bot.py`, `requirements.txt`, `README.md`, `.github/workflows/bot.yml`. На телефоні: *Add file → Create new file*, назву вводиш разом зі шляхом.
3. **Секрети.** Відкрий *Settings → Secrets and variables → Actions → New repository secret* і додай:
   | Назва | Значення |
   |---|---|
   | `TG_TOKEN` | токен бота |
   | `TG_CHAT_ID` | твій chat_id |
   | `TL_EMAIL` / `TL_PASSWORD` | логін і пароль TradeLocker |
   | `TL_SERVER` | назва сервера брокера (та, що вводиш при вході) |
   | `TL_ENV` | `demo` або `live` |
   | `TL_ACC_NUM` | необов'язково: номер акаунта, якщо їх кілька |
4. **Перевірка.** Відкрий *Actions → trading-bot → Run workflow*:
   - `test` → прийде «✅ Бот на зв'язку»;
   - `symbols` → прийде список назв інструментів у брокера;
   - `morning` → прийде ранковий звіт;
   - `once` → бот один раз перевірить сигнали.
5. **Назви інструментів.** Якщо в брокера вони інші (`US500.cash`, `DE40` тощо), відкрий *Settings → Secrets and variables → Actions → **Variables*** і додай `SYMBOLS` з правильними назвами через кому.

Після цього бот запускатиметься сам щодня о 08:00.

## Що можна змінити (через Variables)

| Змінна | За замовчуванням | Що робить |
|---|---|---|
| `SYMBOLS` | `US500,NAS100,GER40,EURUSD,GBPUSD,AUDUSD,NZDUSD,XAUUSD` | список інструментів |
| `SIGNAL_TFS` | `1m,5m,15m,30m,1H,4H,1D` | на яких таймфреймах ловити WT |
| `WT_OB` / `WT_OS` | `60` / `-60` | рівні вершини та дна |
| `WORK_START` / `WORK_END` | `08:00` / `23:00` | робочий час |

Якщо змінюєш робочий час, поправ і години в `cron` у `bot.yml`: зміни мають стартувати за кілька хвилин до початку.

## Нюанси

- M1 і M5 на екстремумах можуть давати багато сигналів. Якщо заважатиме, прибери їх із `SIGNAL_TFS`.
- GitHub іноді стартує розклад на 5–15 хв пізніше. Сигнали, що закрились за цей час, бот надішле одразу після старту.
- GitHub Actions задуманий для збірки й перевірки коду, а не як постійний сервер. Бот у межах лімітів, але теоретично GitHub може обмежити такий репозиторій. Якщо таке станеться, той самий `bot.py` можна запустити на будь-якому комп'ютері чи VPS командою `python bot.py loop`.

## Демо-торгівля на OKX (`okx-demo.yml`)

Окремий запуск, основного бота не зачіпає. Працює **24/7**, кожне повідомлення має позначку **🧪 ДЕМО OKX**.

- Дані й угоди тільки з OKX. Інструменти: `BTCUSDT, ETHUSDT, SOLUSDT` (змінна `OKX_SYMBOLS`; золото/SPY/QQQ вимкнені 21.11 — на вихідних нема ліквідності). Якщо інструмента немає на демо-рахунку, по ньому йдуть лише сигнали.
- Угоди відкриваються під ті самі сигнали, що й віртуальний супровід: вхід за ринком, **стоп одразу на біржі**, ½ там же, де віртуальна, потім стоп у БУ, решта на виході, стопі або за часом (4 дні). На ніч нічого не закривається.
- Ризик **1% від усього балансу USDT** на демо-рахунку (береться з OKX перед кожною угодою, тобто компаунд). Якщо задати змінну `OKX_START_BALANCE`, бот рахуватиме від цієї суми + реальний PnL. Ризик можна змінити через `OKX_RISK_PCT`, плече через `OKX_LEVERAGE` (за замовчуванням 20).
- Підсумок дня о 23:55: R за правилами + $ реально на демо-рахунку + баланс.

**Секрети:** `OKX_DEMO_KEY`, `OKX_DEMO_SECRET`, `OKX_DEMO_PASSPHRASE` (демо API-ключ OKX: права Read + Trade, без Withdraw, без прив'язки IP). Поки їх немає, запуск нічого не робить.

**Перевірка:** *Actions → okx-demo → Run workflow → `okx`*: прийде баланс і список інструментів. `okxreset` — закрити всі позиції і зняти стопи на демо-рахунку.

**Добір (з 22.11):** новий сигнал у той самий бік відкриває ще одну окрему угоду (до `MAX_SAME`=3 на актив/бік). На біржі вони в одній позиції, але в кожної свій обсяг, свій стоп (умовний ордер саме на її контракти, тригер — mark price), своя ½ і свій вихід; PnL рахується окремо. Стоп, що спрацював на біржі, одразу закриває й віртуальну угоду. Розмір позиції рахується від поточної ціни, а не від ціни сигналу.

**З 23.11 (демо):** у бік контексту вхід лише по **закріпу тіла за FVG** після дна/вершини WT (`CTX_ENTRY=fvg`; основний бот — `wt`, як раніше). Дно/вершина тепер включає хвилю, якою WT заходив у зону (свічка зі свіпом/тінню часто ще поза зоною через запізнення WT) — для обох ботів. Тест на демо почато з нуля (стан `okxdemo3`).

**З 23.11 — мультитаймфреймова модель (MTF, `MODEL=mtf` у демо):** бот по колу дивиться M1, M3, M5, M15, M30, H1, H4. Дно (вершина) WT на будь-якому ТФ відкриває сетап; дно має підтвердитись щонайменше на M3 (`MTF_MIN_BASE`). Вхід — закріп тіла за FVG проти нас: шукаємо від ТФ тригера вгору і беремо найстарший FVG, що стоїть поруч (≤ 1.5 ATR M15); закріп рахується закриттям свічки ТФ цього FVG. Стоп під дном. Вихід — протилежний сигнал за тими ж правилами з базовим ТФ ≥ базового ТФ входу, або стоп, або 10 днів. Одна угода на актив, лише в бік контексту дня. Рушій спільний з бектестом (`mtf.py`, `python bot.py mtf`): 6 місяців BTC/ETH/SOL — ≈ +104R / 173 угоди з комісією. Перевірка живого циклу без угод: `python bot.py mtfreplay`.

**З 24.11 (MTF):** новий перехай/дно — новий сетап зі своїм екстремумом і стопом (`MTF_FRESH=1`); дно/вершина лише на M1 теж годиться, якщо закріп — за FVG M15 або старшого ТФ (`MTF_RELAX_TF=15m`). Поки WT хоч на одному ТФ у зоні, закриття тіла за дном/вершиною не ламає сетап, а переносить екстремум. Старший FVG перебиває молодший лише там, де перекриває найближчий FVG (а не далі по ходу ціни). Реверсні виходи шукає окремий рушій за попередніми правилами (екстремум за сетап, дно ≥ M3). Тест на демо з нуля (стан `okxdemo5`).
