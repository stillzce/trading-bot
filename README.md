# Трейдинг-бот у Telegram

**Робочий час:** пн–пт, 08:00–23:00 за Києвом.

- **О 08:00 бот надсилає денний контекст по кожному інструменту.** Контекст визначається денною свічкою (закриття о 17:00 NY = 00:00 Київ) відносно попередньої:
  - закрилась вище PDH або зняла PDL і повернулась → 🟢 BULL;
  - закрилась нижче PDL або зняла PDH і повернулась → 🔴 BEAR;
  - inside-день або outside-день із закриттям всередині → ⚪ нейтрально. Тоді бот бере контекст зі свічки днем раніше, а якщо й вона нейтральна, то ще раніше (до 5 днів).

  До звіту додаються рівні PDH/PDL, WT на D і денний графік.
- **Щохвилини бот перевіряє WaveTrend на M1, M5, M15, M30, H1, H4 і D1.** Сигнал надсилається тільки на екстремумі й тільки за контекстом:
  - BULL → перетин WT вгору на **дні** (≤ −60) → 🟢 LONG;
  - BEAR → перетин WT вниз на **вершині** (≥ 60) → 🔴 SHORT.

  Якщо кілька таймфреймів дали сигнал одночасно, бот надсилає одне повідомлення з графіком старшого з них.

Дані бот бере з TradeLocker. Акаунт треба використовувати **окремий, не пропу**.

## Безкоштовні ліміти — важливо

Бот працює 15 год на день, тобто приблизно 20 000 хвилин GitHub Actions на місяць. Приватний репозиторій дає лише 2000 безкоштовних хвилин, а **публічний — без ліміту**. Тому репозиторій має бути **публічним**:
- секрети (паролі, токени) **не видно нікому**, навіть у публічному репозиторії;
- видно лише код бота, а в ньому немає нічого особистого.

## Налаштування (≈15 хв)

1. **Telegram.** У @BotFather створи бота (`/newbot`) і скопіюй токен. Напиши своєму боту `/start`. Свій chat_id дізнайся в @userinfobot.
2. **GitHub.** Створи **публічний** репозиторій і додай у нього 4 файли, зберігши шляхи: `bot.py`, `requirements.txt`, `README.md`, `.github/workflows/bot.yml`. На телефоні: *Add file → Create new file*, назву вводиш разом зі шляхом.
3. **Секрети.** Відкрий *Settings → Secrets and variables → Actions → New repository secret* і додай:
   | Назва | Значення |
   |---|---|
   | `TG_TOKEN` | токен бота |
   | `TG_CHAT_ID` | твій chat_id |
   | `TL_EMAIL` / `TL_PASSWORD` | логін і пароль TradeLocker |
   | `TL_SERVER` | назва сервера брокера (та, що вводиш при вході) |
   | `TL_ENV` | `demo` або `live` |
   | `TL_ACC_NUM` | необов'язково: номер акаунта, якщо їх кілька |
4. **Перевірка.** Відкрий *Actions → trading-bot → Run workflow*:
   - `test` → прийде «✅ Бот на зв'язку»;
   - `symbols` → прийде список назв інструментів у брокера;
   - `morning` → прийде ранковий звіт;
   - `once` → бот один раз перевірить сигнали.
5. **Назви інструментів.** Якщо в брокера вони інші (`US500.cash`, `DE40` тощо), відкрий *Settings → Secrets and variables → Actions → **Variables*** і додай `SYMBOLS` з правильними назвами через кому.

Після цього бот запускатиметься сам щодня о 08:00.

## Що можна змінити (через Variables)

| Змінна | За замовчуванням | Що робить |
|---|---|---|
| `SYMBOLS` | `US500,NAS100,GER40,EURUSD,GBPUSD,XAUUSD` | список інструментів |
| `SIGNAL_TFS` | `1m,5m,15m,30m,1H,4H,1D` | на яких таймфреймах ловити WT |
| `WT_OB` / `WT_OS` | `60` / `-60` | рівні вершини та дна |
| `WORK_START` / `WORK_END` | `08:00` / `23:00` | робочий час |

Якщо змінюєш робочий час, поправ і години в `cron` у `bot.yml`: зміни мають стартувати за кілька хвилин до початку.

## Нюанси

- M1 і M5 на екстремумах можуть давати багато сигналів. Якщо заважатиме, прибери їх із `SIGNAL_TFS`.
- GitHub іноді стартує розклад на 5–15 хв пізніше. Сигнали, що закрились за цей час, бот надішле одразу після старту.
- GitHub Actions задуманий для збірки й перевірки коду, а не як постійний сервер. Бот у межах лімітів, але теоретично GitHub може обмежити такий репозиторій. Якщо таке станеться, той самий `bot.py` можна запустити на будь-якому комп'ютері чи VPS командою `python bot.py loop`.
